# SmartLife — ระบบอ่านเงินเข้าและเงินออกจากการแจ้งเตือน Android

เอกสารนี้อธิบายเฉพาะระบบนำเข้ารายการเงินจากการแจ้งเตือนของ LINE ธนาคาร
และแอปธนาคารบน Android ตามโค้ดที่ใช้อยู่จริงใน SmartLife

## ระบบนี้ทำอะไร

เมื่อผู้ใช้ยินยอมและเปิดสิทธิ์ **การเข้าถึงการแจ้งเตือน** ให้ SmartLife ระบบจะ:

1. รับเฉพาะการแจ้งเตือนจาก LINE และแอปธนาคารที่กำหนดไว้
2. คัดเฉพาะข้อความที่มีจำนวนเงินพร้อมคำว่า `บาท`, `THB` หรือเครื่องหมาย `฿`
3. วิเคราะห์ว่าเป็นเงินเข้าหรือเงินออก พร้อมจำนวนเงิน ธนาคาร บัญชีสี่หลักท้าย
   ผู้โอน/ร้านค้า ยอดคงเหลือ วันที่และเวลา
4. กันรายการซ้ำระหว่างการแจ้งเตือน LINE กับแอปธนาคาร
5. บันทึกรายการที่มั่นใจสูงลงการเงินจริงโดยอัตโนมัติ
6. ส่งรายการที่ข้อมูลไม่ชัดเจนไปหน้า **รายการที่ต้องตรวจ**
7. ให้ผู้ใช้เปิดรายการภายหลังเพื่อเพิ่มหรือแก้ไขโน้ตได้

ระบบไม่ได้เชื่อมต่อบัญชีธนาคาร ไม่อ่านยอดย้อนหลัง และไม่สามารถโอนเงินได้
ข้อมูลมาจากข้อความแจ้งเตือนที่ Android แสดงบนอุปกรณ์เท่านั้น

## แหล่งแจ้งเตือนที่รองรับ

ระบบ Native Android รับเฉพาะ package ต่อไปนี้:

| แหล่งข้อมูล | Android package |
|---|---|
| LINE | `jp.naver.line.android` |
| K PLUS / KBank | `com.kasikorn.retail.mbanking.wap`, `com.kasikornbank.kplus` |
| SCB EASY | `com.scb.phone` |
| Krungthai / เป๋าตัง | `ktbcs.netbank`, `com.ktb.customer.qr` |
| Bangkok Bank | `com.bbl.mobilebanking` |
| Krungsri | `com.krungsri.kma` |
| ttb touch | `com.ttbbank.ttbtouch`, `com.tmbbank.tmbtouch` |

ตัว parser รู้จักรูปแบบข้อความของ KBank, SCB, Krungthai, Bangkok Bank,
Krungsri, GSB และ ttb หากธนาคารเปลี่ยนรูปแบบข้อความ รายการอาจถูกส่งให้ตรวจแทน

## ขั้นตอนการทำงาน

```text
การแจ้งเตือน LINE/ธนาคาร
        ↓
Android NotificationListenerService
        ↓  กรอง package + ต้องพบจำนวนเงิน
คิวเข้ารหัสในเครื่อง (Android Keystore AES-GCM)
        ↓
ตัว parser แยกข้อมูลและคำนวณความมั่นใจ
        ↓
Firebase Function ตรวจเจ้าของข้อมูลและรายการซ้ำ
        ├─ มั่นใจสูง → บันทึก users/{uid}/transactions
        └─ ยังไม่ชัด → บันทึก users/{uid}/pendingReview
```

เมื่อผู้ใช้เข้าสู่ระบบ `AuthProvider` จะเรียก sync คิวให้อัตโนมัติ และผู้ใช้สามารถกด
**ตรวจคิวตอนนี้** ในหน้า LINE การเงินได้อีกครั้ง หากอินเทอร์เน็ตหรือ Firebase ขัดข้อง
รายการจะยังอยู่ในคิวเข้ารหัสของเครื่องเพื่อรอลองใหม่ ไม่ถูกลบทิ้งเงียบ ๆ

## การอ่านค่าจากข้อความ

### จำนวนเงิน

ระบบหาเงินจากข้อความตามลำดับดังนี้:

- รูปแบบเฉพาะของแต่ละธนาคาร
- คำกำกับ เช่น `จำนวนเงิน`, `ยอดรายการ`, `เงินเข้า`, `เงินออก`, `รับเงิน`, `ชำระ`
- เครื่องหมาย `฿` หรือ `THB`
- ตัวเลขที่ลงท้ายด้วย `บาท` โดยลดคะแนนตัวเลขที่อยู่หลังคำว่า `ยอดคงเหลือ`

จำนวนเงินต้องมากกว่า 0 และไม่เกิน 1,000,000,000 บาท

### เงินเข้าหรือเงินออก

- คำอย่าง `เงินเข้า`, `รับเงิน`, `โอนเข้า` จะถูกจัดเป็น `income`
- คำอย่าง `เงินออก`, `หักบัญชี`, `ใช้จ่าย`, `ชำระ`, `โอนออก` จะถูกจัดเป็น `expense`
- ระบบตรวจสัญญาณเงินออกก่อน เพื่อไม่ให้ข้อความ `หักบัญชีจาก...ชำระให้ผู้รับ`
  ถูกตีความผิดเป็นเงินเข้า
- หากไม่มีคำบอกทิศทางที่ชัดเจน ระบบจะเพิ่มคำเตือนและไม่บันทึกอัตโนมัติ

### วันที่และเวลา

รองรับตัวอย่างรูปแบบ:

- `07/08/69 10:49`
- `7 ส.ค. 69 10:49 น.`
- `2026-08-07 10:49`

ปี พ.ศ. จะถูกแปลงเป็น ค.ศ. และใช้เขตเวลา Asia/Bangkok หากข้อความไม่มีวันที่
ระบบจะใช้เวลาที่ Android รับการแจ้งเตือนและทำเครื่องหมายว่าข้อมูลยังต้องตรวจ

### ข้อมูลอื่น

ระบบพยายามแยก:

- ธนาคาร
- เลขบัญชีสี่หลักท้าย
- ผู้โอน ผู้รับ หรือร้านค้า
- ยอดคงเหลือหลังรายการ
- หมวดหมู่ เช่น Food, Transport, Education, Bills, Shopping, รายได้ และเงินคืน

เลขบัญชีเต็มจะไม่ถูกเก็บเพื่อแสดง ระบบคงไว้เฉพาะสี่หลักท้าย

## เกณฑ์บันทึกอัตโนมัติ

Firebase จะบันทึกรายการโดยอัตโนมัติก็ต่อเมื่อครบทุกเงื่อนไข:

- `confidence >= 0.85`
- `needsReview === false`
- จำนวนเงินมากกว่า 0
- มีชื่อผู้โอน/ผู้รับ/ร้านค้า
- ไม่มีคำเตือนจาก parser

คะแนนความมั่นใจประกอบจากการพบจำนวนเงิน รูปแบบธนาคาร ทิศทางเงิน วันที่
ผู้โอน/ร้านค้า ยอดคงเหลือ และเลขบัญชีท้าย รายการที่ไม่ผ่านเงื่อนไขจะไปอยู่ใน
`pendingReview` และยังไม่กระทบยอดเงินจริง

## การกันยอดซ้ำ

ระบบป้องกันรายการซ้ำสองระดับ:

1. **Exact fingerprint** — SHA-256 จากข้อความแจ้งเตือนที่ normalize แล้ว
2. **Semantic duplicate** — เปรียบเทียบธนาคาร บัญชีท้าย ประเภทเงิน จำนวนเงิน
   ยอดคงเหลือ และช่วงเวลา 5 นาที โดยตรวจช่วงก่อนหน้า/ปัจจุบัน/ถัดไป

ดังนั้น หาก KBank แจ้งรายการเดียวกันผ่านทั้ง LINE และ K PLUS ระบบควรบันทึกเพียงครั้งเดียว
แต่ยอดเท่ากันจากคนละผู้ส่งหรือคนละเวลายังสามารถเป็นคนละรายการได้

## กรณี KBank LINE ไม่แสดงจำนวนเงิน

LINE ของ KBank อาจแสดงเพียงข้อความ `KBank Live แจ้งเตือนรายการเงินเข้า`
โดยจำนวนเงินจริงอยู่ในการ์ดภายในห้องแชต ข้อความ preview แบบนี้ไม่มีจำนวนเงิน
จึงถูกข้ามและ **ไม่สร้างรายการ 0 บาทหรือเดายอดเอง**

หาก K PLUS แสดงการแจ้งเตือนแบบข้อความ เช่น

```text
รายการเงินเข้า บัญชี xxx-x-x1494-x จำนวนเงิน 10.00 บาท
วันที่ 7 ส.ค. 69 10:49 น.
```

ระบบสามารถอ่านจำนวนเงินและเวลาได้โดยตรง การแจ้งเตือนจากแอปธนาคารจึงเป็นแหล่งข้อมูล
ที่แม่นยำกว่าข้อความ preview ของ LINE ในกรณีนี้

## ความเป็นส่วนตัวและความปลอดภัย

- ผู้ใช้ต้องยินยอมใน SmartLife และเปิดสิทธิ์ Notification Access ใน Android เอง
- ระบบไม่สามารถเปิดสิทธิ์นี้แทนผู้ใช้ได้
- อ่านเฉพาะ title/text ของ package ที่อยู่ใน allowlist
- คิวในเครื่องเข้ารหัสด้วย Android Keystore AES-GCM
- คิวชั่วคราวและรายการรอตรวจมีอายุไม่เกิน 7 วัน
- รายการที่บันทึกจริงมี `ownerId` และถูกจำกัดด้วย Firebase Authentication/Rules
- รายการจริงไม่เก็บข้อความแจ้งเตือนดิบ (`rawTextRetained: false`)
- App Check ใช้ป้องกัน callable Functions จากแอปที่ไม่ได้รับอนุญาต
- ไม่มี API key หรือ Firebase debug token ถูกเก็บใน GitHub

## วิธีเปิดใช้งานบนโทรศัพท์จริง

1. ติดตั้ง SmartLife APK ที่มี Native Notification Listener
2. เข้าสู่ระบบ SmartLife
3. ไปที่ **การเงิน → รับเงินจาก LINE ธนาคาร → ตั้งค่าการเชื่อมต่อ**
4. เลือก **ตรวจแจ้งเตือน LINE อัตโนมัติ**
5. กดยินยอม แล้วเปิดสิทธิ์ SmartLife ในหน้า Notification Access ของ Android
6. เปิดการแสดงเนื้อหาแจ้งเตือนของ LINE/แอปธนาคาร
7. ปิด Battery Optimization ให้ SmartLife หากโทรศัพท์หยุดแอปเบื้องหลัง

ฟีเจอร์อัตโนมัติใช้ได้เฉพาะ Android และต้องใช้ APK/Development Build
ไม่สามารถทำงานใน Expo Go และ iOS ไม่อนุญาตให้แอปอ่านแจ้งเตือนของแอปอื่นแบบนี้

## วิธีทดสอบโดยผู้ใช้จริง

1. เปิดสิทธิ์ Notification Access และตรวจว่าสถานะใน SmartLife เป็นเชื่อมต่อแล้ว
2. ให้มีรายการเงินจริงขนาดเล็ก เช่น เงินเข้า 1 บาท หรือเงินออก 1 บาท
3. ตรวจว่าการแจ้งเตือนมีจำนวนเงิน ทิศทาง วันที่และเวลา
4. เปิด SmartLife หรือกด **ตรวจคิวตอนนี้**
5. ตรวจหน้าเงินรายวันว่าประเภท จำนวนเงิน และเวลาตรงกับแจ้งเตือน
6. ส่งการแจ้งเตือนรายการเดียวกันผ่าน LINE และแอปธนาคาร แล้วตรวจว่าไม่เกิดยอดซ้ำ
7. ทดสอบ KBank LINE preview ที่ไม่มีจำนวนเงิน และตรวจว่าไม่มีรายการปลอมถูกสร้าง
8. ปิดอินเทอร์เน็ต สร้างแจ้งเตือน แล้วเปิดอินเทอร์เน็ตและ sync ใหม่ เพื่อตรวจว่าคิวไม่หาย

ทดสอบ parser ในโปรเจกต์ด้วยคำสั่ง:

```powershell
npm.cmd run test:line-import
```

สถานะล่าสุด: ผ่าน 14 checks ครอบคลุมธนาคารหลัก จำนวนเงิน ทิศทาง วันที่/เวลาไทย
KBank preview ที่ไม่มียอด การปิดบังบัญชี และการแยกข้อความหลายรายการ

## ข้อจำกัด

- Android ต้องแสดงข้อความแจ้งเตือนแบบอ่านได้ หากซ่อนเนื้อหา ระบบจะไม่มีข้อมูลให้วิเคราะห์
- การแจ้งเตือนเก่าก่อนเปิดสิทธิ์จะไม่ถูกอ่านย้อนหลัง
- ธนาคารอาจเปลี่ยน package หรือรูปแบบข้อความในอนาคต
- โทรศัพท์บางยี่ห้ออาจหยุด listener เมื่อเปิดโหมดประหยัดพลังงาน
- ระบบอ่านเฉพาะข้อมูลที่ปรากฏในข้อความ ไม่สามารถยืนยันยอดกับบัญชีธนาคารโดยตรง
- รายการที่ข้อมูลไม่ครบจะรอตรวจเพื่อป้องกันยอดการเงินผิด
